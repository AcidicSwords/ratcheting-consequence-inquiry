# RCI v0.4 architecture

This is the implementer-facing architecture for the semantics in
`RCI_Project_Spec.tex` and the sequencing in `PLAN.md`. It does not broaden an
active Goal. Historical files under `docs/spec/sources/` are inputs, not
instructions.

## System shape

RCI is a local, headless Python 3.12 SDK and Typer CLI. Its core is a pure
event-sourced state machine:

```text
command
  -> decide(state, command)
  -> immutable domain events
  -> EventStore.append(stream, expected_sequence, events)
  -> evolve(state, event)
  -> new folded state
  -> plan_next(state)
  -> optional persisted effect request
```

The same lifecycle is exposed through the SDK and CLI. External adapters are
downstream of persisted effect requests. Replay reads events and artifacts only.

The architecture optimizes for:

- lawful behavior with wrong or adversarial semantic payloads;
- an independently inspectable distinction between actuality, interpretation,
  checking, and warrant;
- deterministic offline replay and reference demonstrations;
- exact scope and dependency accounting;
- narrow phase gates and honest unsupported results;
- a path from the small Phase 1–2 kernel into later cognitive, compression,
  recursive-formal, and control work without pretending those capabilities exist.

## Durable authority and logical ownership

The SQLite event ledger and content-addressed artifact store are the only durable
authorities. “Memory owns an object” means one subtree of the folded domain state
is its canonical logical owner; it does not mean a second writable database.

| Owner | Canonical records | Explicitly not owned |
|---|---|---|
| Ledger | Ordered immutable event envelopes and stream sequence | Active theory, mutable domain rows |
| CAS | Exact artifact bytes and digest metadata | Semantic interpretation or warrant |
| `M_E` | Episodic records and artifact/event references | Copies of ledger events, generalized knowledge |
| `M_S` | Immutable `LemmaVersion` semantic records | Support routes and warrant decisions |
| `M_P` | Admitted procedures, probes, contracts, and method manifests | Runtime attempts and returns |
| `M_L` | G2A retention packages, provisional route/scaffold/protocol records, and recovery observations; later licensed capability/residue/compression references | Source history, duplicated support graphs, runtime attempts |
| `W` | Support environments/routes, open dependencies, checks, nogoods, warrant decisions | Semantic proposition versions |
| `A` | Effect requests, attempts, routes, raw returns, decode outcomes, reconstructions | Semantic promotion |
| `Pi` | Prediction seals and warranted mismatch records | Raw return mutation |

The following are projections or ephemeral views:

- active lemma/theory;
- candidate and conflict graphs;
- ordered probe views;
- question-conditioned semantic field;
- reopening and compression-debt views;
- scheduler readiness/order;
- ancestry indexes;
- database indexes, reports, exports, and snapshots.

Every materialized view carries its projection schema version and last processed
event sequence. It can be deleted and rebuilt without changing semantic state.

## Core records and serialization

All domain records and events are strict, frozen, tagged, and explicitly versioned
Pydantic v2 models. One shared model base and one canonical JSON byte serializer
must serve every package. Domain IDs are supplied at the command/effect boundary,
not generated by reducers. Canonical fingerprints use length-delimited,
type-tagged fields and content digests rather than `repr` or insertion-order
accidents.

The durable ledger row and its immutable event payload together contain:

```text
LedgerEvent {
  stream_id, sequence
  event_id, event_type, event_schema_version
  event_bytes, event_digest
}

DomainEvent {
  event_id, inquiry_id, occurred_at
  kind, schema_version
  typed payload and exact artifact/provenance references
}
```

Stream sequence is assigned by the ledger transaction, not invented inside the
domain event. Event-specific metadata is carried by the typed payload or a pinned
artifact reference; there is no untyped catch-all metadata field.

Metadata that is operational but nondeterministic—capture time, adapter usage,
hardware/runtime details—must be supplied by the effect boundary and then
persisted. Reducers never invent it.

## SQLite ledger, CAS, snapshots, and projections

### Ledger

The initial storage schema is version 1. SQLite configuration and append behavior:

- WAL mode and foreign keys enabled;
- `BEGIN IMMEDIATE` for an append transaction;
- expected stream sequence checked inside the transaction;
- unique constraints on event ID and stream/sequence;
- all events for one command appended atomically;
- one writer path per inquiry;
- a typed concurrency error on a stale expected sequence;
- a bounded busy timeout, never an inference that work is impossible.

### Content-addressed artifacts

Large/raw prompts, returned bytes, certificates, diagnostics, and later compressed
representations live in CAS. An artifact reference contains digest, byte count,
media type, encoding/capture-boundary metadata, and optional declared kind.

Write order is:

1. write a temporary file in the destination filesystem;
2. flush, publish atomically, and verify the digest;
3. append the event that references the artifact.

A crash may leave an unreferenced artifact that can be collected later. An event
must never point at absent or digest-mismatched bytes.

### Snapshots

A snapshot pins stream sequence, folded-state schema version, and source digest.
It is an acceleration only. Loading fails closed on unknown versions or integrity
errors and falls back to replay when safe.

### Projections

Projection rows and the checkpoint advance in one transaction. Handlers are
idempotent. A query that requires current data either catches the projection up
or folds the authoritative stream. No write path accepts a projection row as a
semantic command input merely because it is convenient.

## Effects, attempts, raw returns, and checking

### Identities and cardinalities

`effect_request_id` identifies logical work. `attempt_id` identifies one delivery.
A request can have several attempts; an attempt has exactly one terminal outcome;
a request accepts at most one resolution.

`NoAttempt` is a plan disposition. It does not invent an attempt ID. Attempt
outcomes are:

- `NotPresented`: the boundary is known not to have been crossed;
- `PresentationUnknown`: crossing the boundary cannot be established;
- `CaptureFailed`: a response may have existed but exact bytes were not durably
  captured;
- `Cancelled`;
- `Returned`: an immutable external-return record exists.

Timeout and transport reasons remain typed. Retrying after presentation uncertainty
is an at-least-once decision and must preserve the uncertainty.

### Lifecycle

```text
StepPlanRecorded
  -> EffectRequested
  -> NoAttemptDisposition | (EffectAttemptPlanned -> EffectAttemptStarted)...
  -> one EffectAttemptOutcome per started attempt
  -> [Returned owns immutable ExternalReturn]
  -> DecodeOutcome
  -> [Decoded owns a canonical result]
  -> EvidenceRecorded
  -> CheckerVerdictRecorded
  -> WarrantDecisionRecorded
  -> [EffectResultAccepted]
  -> [LemmaPromoted]
```

`ExternalReturn` is a distinct immutable record owned by the typed `Returned`
outcome; the outcome event therefore captures their relation atomically. No
projection may independently mutate either side of the relation.

### Route snapshot

A registry-owned `RouteDefinition` describes allowlisted executable behavior. A
per-attempt `RouteSnapshot` records what was actually resolved:

- backend, adapter, and version;
- addressed source and redacted endpoint/channel;
- execution-environment and request/action digests;
- ordered planned and observed transform metadata;
- capture-boundary contract;
- source/policy manifest versions.

Credentials and unrestricted environment variables are never stored. Addressed
source belongs to the route; source-reported identity/revision belongs to the
return; semantic source claims belong to the decode.

### Raw payload

The earliest contracted captured bytes are stored unchanged. A post-SDK object is
called a captured payload, not wire bytes, unless the adapter truly captured the
wire representation. Any decompression or parse performed before capture appears
in the route’s observed transform chain.

Presence is not modeled with a nullable artifact reference. The bytes for JSON
null are a present artifact and remain distinct from empty bytes, an empty JSON
string, numeric zero, and false.

### Decode, check, and warrant

Decode is a strict union: `Decoded`, `Malformed`, `Unsupported`, or `Failed`.
Only `Decoded` produces a `DecodedResult`. The result role is itself a
discriminated union rather than an optional-field bag.

Checking is separately `Valid`, `Invalid`, `Indeterminate`, `Timeout`,
`Unsupported`, or `Failed`. An independent checker receives the immutable return
and decoded proposal where relevant. It validates the proposition/evidence rather
than trusting a backend’s status string.

A policy then assigns a warrant decision. Promotion is another atomic semantic
transition. Late or duplicate returns can be retained and rejected, but they do
not replace the accepted resolution or promote a second result.

## Claims, conflicts, reification, and formal backends

Claims preserve question ID/version, bound IDs, opaque payload, scope, provenance,
status, representation level, and typed relations. L0 is total: any bytes or text
accepted by the input boundary remains inert and inspectable.

At L0, conflict requires exact proposition identity, opposite polarity, compatible
role, identical bound referents, and scope. Free prose is never parsed opportunistically
to create contradiction.

Phase 2 reification targets a restricted Boolean/finite-enum AST:

- literals and symbol references;
- equality;
- negation, conjunction, disjunction;
- implication and equivalence.

There is no arbitrary code or quantifier. Schema parsing fails closed. An independent
interpreter and exhaustive finite enumerator are the base authorities. The optional
Z3 translator is checked differentially over bounded formulas.

Decoded backend roles map to typed events and follow-up obligations. Failure and
Unknown preserve their exact cause. No return receives a stronger semantic
interpretation than its checker supports.

## Support routes and warrant

A semantic lemma version and its epistemic support are separate:

```text
LemmaVersion {
  id, proposition_or_relation, scope, applicability,
  source_claim_refs, predecessor_edges
}

SupportEnvironment {
  id, normalized_assumptions, scope, binding_revision,
  finite_universe_ref, independent_realizability_check_ref
}

SupportRoute {
  id, conclusion_ref, environment_ref,
  required_dependencies, open_dependencies,
  justification_refs, certificate_check_ref,
  warrant_refs, provenance_refs
}
```

The open boundary belongs to a support route because it depends on that
environment. A lemma is active when applicability holds and at least one standing
minimal route is closed. Alternate routes are not flattened into a single
disjunction or one shared dependency list.

Minimality is a subset antichain only within an identical conclusion/scope/binding/
applicability/universe/policy class. Dominated routes stay in history. A warranted
nogood deactivates only environments that contain it.

The G1 support policy is grounded and acyclic. Ungrounded recurrence cannot
discharge itself. Cyclic mathematical proof syntax can be retained as inert
certificate material, but a later independent checker must validate it as a leaf;
it is never represented as an active support-graph cycle. Semantic predecessor
ancestry is independently acyclic and supports split and merge edges.

Promotion creates an L3 active view joining `M_S` and `W`. Guard, support-route,
and nogood standing changes are append-only events. Scope, binding, universe, and
policy changes are exact inputs to the pure `TheorySelector`; selecting mismatched
pins deactivates affected views and selecting the prior pins reopens them. Neither
path writes an active-theory store or deletes semantic/support history.

## Questions, scheduling, and semantic generation

Question contracts are registry-owned behavior with immutable data templates.
They declare typed arguments, preconditions, a total L0 binder, lawful updates,
and follow-ups. Templates cannot execute anything.

The full catalog is retained as replayable metadata, but only versioned profiles
can schedule contracts. `core-v1` is the G1 Phase 1 profile:

1. obligation characterization;
2. same-class variation;
3. minimal boundary crossing;
4. factor proposal;
5. necessity counterexample;
6. sufficiency counterexample;
7. conflict localization;
8. residual characterization.

The scheduler deduplicates by obligation kind, normalized bound arguments, scope
fingerprint, and binding revision. The attempt key adds contract ID/version.
Stable ready order is safety, priority, dependency depth, creation sequence, and
stable ID. Defaults are 100 reducer steps, three attempts for one attempt key, and
60 seconds for an external effect.

Manual and scripted generators are base-test authorities. The optional OpenAI
adapter only renders bounded semantic content. It cannot select its own tools,
question, policy, or warrant.

## Recurrent probes and the G1 cognitive slice

A recurrent probe is identified by contract/version, binding, scope, applicability,
comparison policy, and horizon—not wording alone. Comparable events form an
ordered `ProbeTrace`. Any persistence, change-point, covariation, recurrence, or
path-dependence proposal remains a claim.

When isolation matters:

```text
fresh external observation
  -> immutable raw return
  -> decode
  -> expose prior trace
  -> compare
  -> provisional pattern/mismatch
```

A prediction used for mismatch is immutable and precedes the attempt. A mismatch
requires an actual decoded return, not timeout or capture failure.

G1 retains the thin lineage:

```text
attempt/return -> episodic record -> candidate reconstruction
               -> checked SemanticDelta -> semantic promotion
```

Reconstruction detail is not history. Episodic recurrence is not a generalized
semantic invariant. G2A adds deterministic structural retrieval, ambiguous
candidate reconstruction, non-compressive retention registration, and measured
reacquisition. G2B separately adds consolidation, reconsolidation,
semantic-field evaluation, and candidate learned probes.

## Compression architecture (specified now, executable later)

### Two folds and explicit carriers

```text
immutable ledger prefix
  -> pure aggregate fold Phi_agg
  -> InquiryState / complete authoritative standing
  -> binding-specific partial history derivation rho_B
  -> realized history Hist_B
  -> configuration projection p_B -> X_B
  -> validated retained representation q_H -> S_H
```

`Phi_agg` is replay reconstruction and `q_H` is consequence-relative
representation; they are never interchangeable. Ledger succession is not realized
succession. Carrier roles are pinned by versioned binding/carrier manifests and are not
inferred from Python types. `ProbeTrace` remains one comparable subtrace,
`RetentionPackage` remains a G2 package, and `MemoryPatchCandidate` remains semantic
repair.

An exact history-state contract separately validates protected consequence
factorization and continuation compatibility. Deterministic recursive execution may use
`q(h . u) = U(q(h), u)` only for binding-declared realized extensions. Determinations
descend only after exact saturation. The authoritative aggregate is never replaced or
compressed.

The permanent pipeline is:

```text
QUOTIENT -> REPARAMETERIZE -> APPROXIMATE -> RESIDUE -> REOPEN
```

The core distinguishes:

- exact consequence equivalence from licensed approximation;
- object/source reconstruction loss from consequence loss;
- present use, object regeneration, direct consequence evaluation, and
  reacquisition as independent recovery relations.

G3 separates `CompressionContract`, independent `CompressionValidation`,
policy `CompressionLicense`, and `CompressionApplication`. Exact and approximate
licenses are tagged variants. A reported or empirical loss of zero is not exact.

G3A-H additionally implements explicit `CarrierRole`/carrier contracts, binding-derived
history, `ExactCompressionLicense`, `RecoveryLicense`, `PathResidue`, route-capability
links, and representation-successor decisions. A strict successor preserves still-valid
predecessor capabilities, adds typed gain, and has standing warrant; otherwise the
candidate is rejected, retained provisionally, or placed on an incomparable frontier.
G3A-L later plugs the exact linear binding into this generic contract.

In G2A, a `RetentionPackage` references owned typed artifacts and may reference
separate provisional `DirectUseRoute`, `ReconstructionRoute`,
`ConsequenceEvaluationRoute`, and `ReacquisitionRoute` declarations. These are
unlicensed candidates, not exposed protected capabilities under RCI-049.
`ReconstructionRoute` describes reconstruction without substantial new external
learning and is not the licensed G3 `ObjectRegenerationRoute`. Their presence
cannot establish retained learning, support, warrant, or promotion.

G3 joins versioned route declarations to a `RecoveryLicense`, fidelity/loss and
protected competence/query contracts, implementation version, dependencies,
support route, provenance, failure behavior, and fallback. Only that licensed
view is a retention capability. Combined capability is derived from the licensed
routes that exist. ADR-0009 amends ADR-0006's premature statement that every G2
route already carries a license.

`ReacquisitionRoute` points to a `ReacquisitionScaffold` that may retain cues,
probes, representations, methods, known boundaries/failure regions,
prerequisites, and provenance. The scaffold does not contain or warrant the
target competence. Activating it creates an ordinary inquiry whose eventual
return/check/warrant path can establish recovery.

Recovery evaluation pins the target competence, protected horizon, finite
universe, binding, context, baseline state or cohort, protocol, evaluator,
evidence access, budget, and comparison policy. A cost vector has matching named
axes and exact nonnegative values. The derived `RecoveryFrontier` keeps
nondominated observations. A G2A `RecoveryComparison` can report strict Pareto
improvement only when every retained cost is no worse and at least one is better;
incomparable vectors establish no advantage. Independent checking leaves the
comparison provisional/soft. There is no repository-wide scalar score, and G2A
cannot create hard warrant or a `RecoveryLicense`.

Reacquisition uses the existing effect protocol. New version-1 events represent
the parent request and parent/child linkage as a resumable saga; every partial
prefix stays open. G1 event schemas remain unchanged. Folded-state, snapshot,
and projection schemas may advance, while incompatible derived state rebuilds
from the ledger and archived G1 streams retain their G1 semantics.

Compression transports open dependencies and authoritative ancestry into residue.
Reopening is triggered by horizon, query distribution, loss, bound, budget,
evaluator, support, scope, binding, or policy changes. Without recoverable residue
or a reacquisition route, the result is Unknown. Reopening can select direct use,
reconstruction, consequence evaluation, provenance retrieval, or a new
reacquisition inquiry. Forgetting is represented as a checked reduction in
future recovery capacity, not inferred from failed recall or deletion.

Representation/path residue is distinct from an epistemic open dependency. Generic
reopening is exact factorization failure: a new protected consequence separates inputs
that the incumbent representation identifies. A route can expose a protected compressed
capability only by joining the unchanged G2 package/route to a standing validation,
compression application, and route-specific recovery license.

The corrected linear theorem is a G3A binding, not a core vector assumption.
Exact tests use rational/symbolic evidence. Thresholded numerical rank is an
approximate license candidate only.

G2A makes structural retrieval, candidate reconstruction, non-compressive
retention registration, scaffold activation, and measured reacquisition inquiry
executable. G2B adds deterministic consolidation/reconsolidation, conservative
semantic-field evaluation, and checked candidate learned probes. G3 adds exact/approximate compression,
route-specific recovery licences, licensed frontier budgets, residue, and
reopening. None is part of the sealed G1 baseline.

G2B uses four explicit pipelines. `consolidation-interleave-v1` records a source-
prefix-pinned checkpoint before admitting an ordinary generalization claim and its
attacks. `MemoryPatchCandidate` proposes versioned repair, while a separately checked
application appends the successor lemma, correction, and dependency-preserving
`ReconsolidationLink`. `conservative-question-field-v1` derives a bounded view and records
only a diagnostic evaluation. A `RepresentationGap` may propose an inert learned probe;
`finite-stratified-holdout-v1` and `g2b-probe-admission-v1` gate procedural admission.
None of these paths writes a semantic fact, licence, control certificate, or writable
semantic-field authority.

## Future opaque controlled-memory benchmark

The archived opaque-environment note is a future benchmark specification. It is
not an event-store primitive, a privileged memory-map API, or a current
acceptance fixture. It reuses ordinary attempts, external returns, probes,
support routes, predictions, retention, and compression through a binding.

| Stage | Reusable capability | Benchmark status |
|---|---|---|
| G1 | Immutable raw returns, attempt alignment, inert interpretation, prediction sealing, basic probes | Building blocks only; no opaque benchmark claim |
| G2A | Structural retrieval, candidate reconstruction, provisional retained routes, reacquisition scaffolds and soft comparison | Individually testable candidate relations; no licensed capability |
| G2B | Consolidation/reconsolidation, semantic-field evaluation, candidate learned procedures/probes | Hypotheses only; no licensed recovery |
| G3 | Consequence-relative quotient, recovery licences, compression, reopening, relearning-frontier measurement | Individually testable capabilities |
| G4 | Richer formal identification and a versioned PSR/system-identification native binding | Research-gated |
| G5 | Independently checked control synthesis/actualization | Research-gated |
| G6 | Multi-backend evidence for learned relations | Research-gated |
| G7 | Pinned end-to-end environment, transfer conditions, evaluation frontiers, hardening | Benchmark acceptance |

The benchmark keeps raw memory returns authoritative and withholds semantic
variables. It must distinguish raw difference from semantic difference,
correlation from dependency, separator from cause, predictive state from control,
and compression from forgetting. A Predictive State Representation adapter is
preferred to inventing a hidden-state formalism. The linear consequence theorem
is available only after a warranted vector representation and linear protected
query family exist; raw bytes and arbitrary environment dynamics do not satisfy
that precondition.

## Optional native and Docker adapters

G1 may provide a pinned Linux parity image, but Docker is not a base requirement.
Native compression adapters begin in G3C and use a generic container port:

- human/registry-allowlisted image pinned by digest;
- no image pull during offline execution;
- explicit argument vector and bounded JSON/artifact protocol;
- nonroot, read-only root filesystem, no network, all capabilities dropped,
  no-new-privileges, bounded CPU/memory/pids/time/output;
- only captured temporary input/output mounts;
- no credentials, Docker socket, ledger/CAS database, or live source mount.

The container’s stdout/stderr and output artifacts enter the ordinary
Attempt/ExternalReturn/Decode/Check path. Adapter output never warrants itself.
Docker, GPU, or image absence yields a typed unsupported/no-attempt disposition.

EDEN/DRIVE remain catalog-only until software licensing is resolved. TurboQuant
remains catalog-only until an official licensed implementation is available.
QJL is the first eligible research candidate but is CUDA/Linux-heavy and
nonblocking.

## Repository modules and dependency direction

Create modules only when exercised:

```text
src/rci/
  core/          shared strict models, IDs, events, serialization, reducers
  persistence/   SQLite ledger, CAS, snapshots, projections, schema bootstrap
  questions/     contract data, profiles, compiler, registry
  claims/        claims, conflicts, correction relations
  orchestration/ commands, scheduler, plans, effect protocol
  formal/        restricted AST, interpreter, finite enumerator
  warrant/       support routes, independent checks, policy, active views
  probes/        recurrent identity, traces, prediction/mismatch
  generators/    manual, scripted, optional OpenAI
  backends/      exhaustive, optional Z3, later container adapters
  bindings/      circuit, route graph, later linear/compression bindings
  memory/        structural retrieval and non-compressive retention records
  recovery/      reacquisition saga, exact costs, frontier/comparison
  evaluation/    deterministic traces and nonblocking live evaluations
  backlog/       governed shadow reconciliation
  cli/           Typer surface over the SDK
```

`core` has no dependency on adapters, CLI, or persistence. Domain packages can
depend on core schemas. Persistence serializes domain events without importing
execution policy. Orchestration depends on ports, not concrete optional adapters.
CLI is a thin caller of the public SDK.

Base production dependencies remain Pydantic v2 and Typer. OpenAI and Z3 are
extras in G1; SymPy and NumPy are not added until G3A/G3B. Research repositories
are never copied into core.

## G1 implementation checkpoints

1. **Foundation:** package metadata, shared model/serialization seams, IDs,
   event envelope, scope/binding records, event vocabulary, documentation, CI.
2. **Persistence:** SQLite bootstrap/append/OCC, CAS, snapshot and projection
   protocols, deterministic replay/export, crash tests.
3. **Inquiry kernel:** commands, pure reducers, claims/conflicts/obligations,
   catalog/profile registry, scheduler, manual/scripted answers.
4. **Effects:** request/attempt/route/raw return/decode/check resolution with
   cardinality and duplicate tests.
5. **Formal Phase 2:** restricted AST, interpreter/enumerator, attacks and result
   mapping, optional Z3 differential checks.
6. **Support/warrant:** environments, route-specific boundaries, antichains,
   nogoods, activation, promotion, invalidation, cycle and ancestry checks.
7. **Cognitive spine:** probe identity/trace, prediction seal, mismatch,
   reconstruction and SemanticDelta separation.
8. **Vertical surfaces:** SDK/CLI parity, both deterministic bindings, replay,
   inspection/export, shadow backlog and security boundaries.
9. **Complete gate:** record exact commands and returns in
   `docs/verification.md`; leave every unrun or failed conclusion unverified.

## Governed dogfooding

`.rci/config.toml` is the only tracked backlog policy. Runtime state is ignored.
Reconcile is dry-run by default. Manual G1 apply may append create, exact-dedupe,
rank, and block only. Close remains proposal-only.

Evidence runners see an explicit captured temporary workspace and receive no
network, source-writing, Git mutation, policy editing, packaging, deployment,
release, or permission-expansion port. RCI may propose obligations and ADR
changes; human review and CI authorize changes.
