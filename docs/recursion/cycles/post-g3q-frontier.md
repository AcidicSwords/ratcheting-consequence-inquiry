# Post-G3Q recursive frontier inquiry

## Anchor and standing

This bounded selection cycle began from clean protected-main commit
`4d89bb776181dd0b7885b0e0dd1042426d0456ca`, after the G3Q implementation and its hosted
verification evidence had both been promoted. G1, G2A, G2B, G3A-H, G3R, and G3Q were
standing verified capabilities. No later implementation Goal was active.

The standing limitation is exact: G3Q can ask a confined generated project question and
route an admitted return, while G3R can seal a Goal, but only the external development
orchestrator translates the former into the latter. That join is not recorded, replayed,
or independently attacked.

## How the project changes the development agent

RCI does not alter Codex model weights, training, context limits, or platform
permissions. It changes the development process around Codex. In particular, it turns
ephemeral judgments into durable typed candidates, exact anchors, counterexamples,
tests, review returns, protected checks, and reacquisition material. A later context can
therefore recover why a change exists without trusting the confidence or memory of the
context that authored it.

This cycle used observed failures rather than a generic claim that an agent is fallible:

- the orchestrator still manually translated the G3Q frontier into the G3Q Goal;
- the replaceable handoff retained the implementation merge SHA after a later evidence
  closeout commit had become the exact protected-main anchor;
- an initial README closeout omitted two verified milestones;
- concurrent Windows test runs collided on a shared SQLite temporary path;
- branch-protection read-back exposed a missing required check, and a broad API update
  failed because it assumed organization-only restrictions on a personal repository;
- one independent reviewer was unavailable, and another issued a false authority-chain
  objection because it did not account for GitHub's documented rebase SHA rewrite.

The repairs were not “trust Codex more.” They were serial reruns, exact API read-back,
typed pins, honest documentation, an alternate independent review route, and comparison
against primary platform semantics. Independent returns remain evidence and may
themselves be invalid or indeterminate.

## Regenerative distinguishing question

The G3Q-shaped candidate for this cycle is data-only:

```text
Question:
  Which missing bridge changes whether a checked project-question return can become
  the next immutable implementation contract?

Typed referents:
  anchor-main-4d89bb7
  limitation-question-return-to-goal
  frontier-post-g3q-v1

Return goal-derivation-required:
  downstream state = compile-confined-goal-candidate
  obligation kind = implementation

Return method-transport-required:
  downstream state = bind-native-method-first
  obligation kind = method

Comparison policy:
  consequence-distinction-v1

Consumer:
  frontier-builder

Falsifying attacks:
  manual-orchestrator-bypass
  method-before-goal-bypass
  actuator-without-goal
```

The returns differ consequentially. The first makes project reasoning replayable before
source change; the second improves the method repertoire but leaves the Goal translation
manual. Any unmatched answer remains an unresolved residual and cannot select a Goal.

## Dogfood frontier

The existing `derive_capability_frontier` implementation was run over the five surviving
candidates in original and reversed order. The results were exactly equal. All candidates
preserve `g1`, `g2a`, `g2b`, `g3a-h`, `g3q`, and `g3r`; each has a different typed gain,
so none dominates another.

The exact cost axes are bounded inventories for this decision, not universal measures:

- `missing-seams`: independently implementable joins still needed before the candidate's
  discriminator can run;
- `authority-risk-boundaries`: new privileged or policy-sensitive boundaries that its
  implementation must defend.

The counts are auditable inventories rather than impressions. G3G needs a candidate
compiler and an admission-to-existing-Goal join; its one new policy-sensitive boundary is
the confined controller/registry decision. Native-method binding needs applicability and
adapter joins and crosses method/dependency policy. G3A-L needs carrier, theorem,
validation, and application joins and crosses dependency policy. The actuator needs
worktree, bounded execution, evidence-capture, and lifecycle joins while defending source,
command, Git, credential, and promotion boundaries. G4 needs syntax/translation,
predecessor, invariant, checker-evidence, and aggregate joins while crossing native-solver
and solver-trust policy.

| Candidate | Typed gain | Missing seams | Authority-risk boundaries |
|---|---|---:|---:|
| autonomous Goal synthesis | independent checkability | 2 | 1 |
| native-method binding | new method | 2 | 2 |
| G3A-L exact linear binding | executable relation | 4 | 1 |
| isolated candidate actuator | development recovery | 4 | 5 |
| G4 recursive formal engine | scope extension | 5 | 2 |

The derived frontier is `ready`; every pair remains explicitly incomparable, while
`candidate-autonomous-goal-synthesis` is the componentwise cost-minimal reversible
candidate with a lawful discriminator. This selects which discriminator to run first,
not a total roadmap ranking.

## Attacks and disposition

Goal synthesis is not necessary for all software progress: Codex can manually author a
Goal, so the `manual-orchestrator-bypass` succeeds. The surviving narrower relation is
that RCI cannot itself preserve and replay how an admitted return became the sealed
implementation target. Native-method research also bypasses no part of that relation.
G3A-L and G4 add valuable mathematics but do not change it. An isolated actuator before
an exact target increases authority risk and can only automate an unrecorded decision.

The selected bounded successor is therefore confined implementation-Goal synthesis,
named G3G. It compiles only exact owned records and allowlisted profiles into an inert
candidate, then requires separate admission before the existing Goal seal. It has no
source-writing or execution authority. G3A-L, native-method binding, isolated actuation,
and G4 remain on the frontier.

Goal-oriented requirements engineering, requirements/specification separation, bounded
counterexample-guided synthesis, and typed algorithm selection were consulted only for
their native relations and assumptions; their sources and transport limits are recorded
in ADR-0014. No imported method warrants the selected architecture by itself.

## Consequential residue

G3G is selected at the exact protected-main anchor above, but this cycle implements no
G3G code and introduces no dependency, event/schema change, or authority expansion. A
separate no-budget G3G Goal is required before implementation. G3A-L, native-method
binding, isolated candidate actuation, and G4 remain nondominated future work.
