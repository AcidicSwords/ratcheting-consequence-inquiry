# G3Q regenerative-question recursive inquiry

## Anchor and limitation

G3Q began from clean protected-main anchor
`b20935c712e3bd0a3d16aa5445c40c5297eb77c7`. G3R could preserve and independently admit
an inert `QuestionContractCandidate`, but admission could not make the operator available
to ordinary scheduling. The consequential separator was whether one exact admitted
data-only contract could open a typed project obligation and yield distinct downstream
consequences while every unadmitted, stale, malformed, ambiguous, or context-mismatched
candidate remained inert.

## Successor and preservation

The successor adds a derived `CompiledQuestionContract` projection for the confined
`recursive-project-v1` profile. It reuses sealed candidate, decision, obligation, effect,
claim, replay, and warrant records. It adds no event kind, folded-state field, snapshot
migration, dependency, source-writing port, Git port, or policy-selection authority.
Generated answers remain provisional. Exact declared returns open allowlisted ordinary
downstream obligations; every other return opens an unclassified residual. Neither path
creates a checker verdict, warrant, promotion, procedural fact, or retained-state licence.

## Attacks and development-agent failures

The recursive loop materially changed the candidate before promotion:

- self-review found that a generated obligation could carry a limitation marker without
  proving the exact owned limitation binding; the final compiler and SDK require equality;
- sibling admission decisions could conflict; the final compiler requires exactly one
  total decision and its exact active policy;
- one malformed candidate initially risked suppressing the whole generated registry; the
  projection now omits only the invalid candidate and preserves unrelated questions;
- duplicate contract keys could make lookup order authoritative; every colliding key is
  omitted until the ambiguity is resolved;
- partially present generated-envelope pins could blur built-in and generated execution;
  the envelope now requires the complete pin set or none;
- overlapping local pytest invocations contended for the same Windows SQLite temporary
  path; the collided run is explicitly excluded from evidence and the canonical command
  was rerun serially;
- the requested hosted reviewer returned a usage-limit notice. It remained
  `Indeterminate`; a separate read-only GitHub Copilot CLI review of the exact committed
  diff supplied the fresh review return instead;
- the first protection read-back showed that the new regenerative check had not entered
  the required set. A broad update attempt then returned HTTP 422 because personal
  repositories cannot carry organization user/team restrictions. The exact status-check
  subresource was updated instead, and a second read-back proved all seven checks before
  merge.
- the first evidence-closeout review rejected an opening README milestone list that
  omitted verified G3R and G3Q; an honest follow-up commit corrected it. The next review
  incorrectly treated GitHub's expected Rebase-and-Merge SHA rewrite as a broken authority
  chain. GitHub's primary documentation, the PR API, identical tree IDs, identical parent,
  and empty diff falsified that diagnosis. External review is evidence, not authority, and
  must itself survive exact comparison.

These are not claims that Codex became intrinsically more intelligent or that its model
weights changed. The gain is procedural and durable: transient assumptions became exact
types, adversarial tests, policy read-backs, immutable evidence, and reacquirable failure
boundaries. Compiler, type checker, tests, independent review, GitHub policy, and hosted CI
acted as returns that the candidate implementation did not control.

## Consequential residue

G3Q changes how the project can ask, but not yet how it binds an established native method
to a typed relation, synthesizes an immutable implementation Goal from question returns,
or actualizes a candidate in a bounded worktree. G3A-L, native-method binding, autonomous
Goal synthesis, isolated candidate actuation, and G4 therefore remain frontier members.
This cycle does not rank or activate one by intuition; a fresh recurrence from the exact
promoted anchor must compare their next consequences.
