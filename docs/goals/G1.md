# Proposed Goal G1: Foundation, Phases 1–2, and bounded cognitive spine

Create this Goal without a token budget.

## Target

Build and verify the RCI v0.3.1 G1 reference milestone described by `PLAN.md`.

Follow the root `AGENTS.md`. Treat `RCI_Project_Spec.tex` as semantic authority,
`PLAN.md` as approved architecture and sequence, the active Goal as the
completion boundary, and `docs/requirements-matrix.md` as the honest coverage
ledger. Preserve unresolved ambiguity in the matrix or an ADR; do not silently
settle it in code.

Deliver an installable, deterministic, offline-first Python 3.12 SDK and Typer
CLI with:

1. **Foundation and authority**
   - PEP 621/`uv` packaging, Apache-2.0 license, documentation, and independent
     Windows/Linux base and all-extras CI lanes.
   - Strict frozen versioned Pydantic v2 records, one canonical serializer, typed
     IDs, scope/binding/guard/universe/policy records, and immutable domain
     events.
   - Pure `decide(state, command) -> events` and
     `evolve(state, event) -> state` transitions.

2. **Durable event spine**
   - SQLite WAL append-only ledger, atomic expected-sequence checks, one logical
     writer per inquiry, idempotent schema bootstrap, fail-closed unknown schema
     versions, and crash/resume consistency.
   - Content-addressed artifacts with tamper detection, rebuildable projections,
     validated snapshots, deterministic effect-free replay, and byte-identical
     canonical export.
   - Ledger/CAS as the only durable authorities; `M_E/M_S/M_P/M_L/W/A/Pi` are
     single logical owners in folded state, while active theory and other views
     remain rebuildable.

3. **Inquiry and effect kernel**
   - Immutable claims, obligations, conflicts, candidates, corrections,
     residuals, guards, warrant/support records, and deterministic scheduler.
   - Full immutable question catalog as data, but only the admitted `core-v1`
     profile schedulable: obligation characterization, same-class variation,
     minimal boundary crossing, factor proposal, necessity counterexample,
     sufficiency counterexample, conflict localization, and residual
     characterization.
   - Deterministic obligation fingerprints/deduplication, dependency ordering,
     100 reducer-step default, three attempts per identical attempt key, and
     60-second external-effect timeout.
   - Persisted effect request before execution; at-least-once attempts;
     first-result idempotent acceptance; typed `AttemptOutcome` and
     `ReturnRoute`; `NoAttempt` only as a plan disposition; exact raw
     `ExternalReturn` captured before decode; separate decode, check, warrant,
     and promotion.

4. **Phase 2 formalization and warrant**
   - Restricted inert Boolean/finite-enum AST, typed reification outcomes,
     independent interpreter and exhaustive enumerator, and optional Z3
     translator with bounded differential tests.
   - Necessity, sufficiency, prerequisite, localization, generalization, and
     actualization attack profiles with canonical typed results.
   - Route-specific support environments and open dependencies, minimal-support
     antichains, nogoods, guarded applicability, linked immutable
     `WarrantedLemma`/L3 views, and atomic positive warrant/ancestry-cycle
     rejection.
   - Exact policy: model/reification output has no warrant; independently checked
     witness applies only to its exact existential scope; exhaustive UNSAT is
     hard only for a declared closed finite universe; Z3-only UNSAT is
     solver-trusted soft support; timeout/failure/unsupported/unknown never
     fabricate stronger conclusions.

5. **Bounded cognitive spine**
   - Comparable recurrent probes with immutable traces, fresh-observation
     isolation, sealed predictions before attempts, actual-return mismatch, and
     candidate reconstruction.
   - Keep raw history, reconstruction detail, semantic `LemmaVersion`, support,
     and `SemanticDelta` separate. Unknown relevance remains preserved rather
     than silently forgotten.
   - Manual and scripted generators support every blocking test offline. The
     optional OpenAI Responses adapter uses an explicitly configured model,
     local stateless context, no model tools, bounded output, `store=False`, and
     preserves raw L0 output and status/usage.

6. **Reference demonstrations and surfaces**
   - SDK/CLI parity for start, step, run, resume, inspect, submit answer, replay,
     and export, plus contract, evaluation, database, and backlog groups.
   - Eight-state circuit
     `lamp_on = switch_closed AND (main_power OR backup_power)`: refute
     main-power necessity, refute available-power sufficiency with an open
     switch, and exhaustively establish switch-closed necessity.
   - Route graph `start -> gate -> target` and
     `start -> bypass -> {target, dead_end}`: refute the gate prerequisite and
     distinguish may-reachability from must-control.
   - Both demonstrations run deterministically without OpenAI or Z3.

7. **Governed dogfooding**
   - Tracked human-owned `.rci/config.toml` and ignored runtime state.
   - Backlog reconcile is shadow/dry-run by default. Explicit manual apply may
     append only create, exact-dedupe, rank, and block. Close remains
     proposal-only.
   - Evidence runners use explicit argument arrays, bounded time/output, captured
     temporary workspaces, and no network. They expose no source-writing, Git
     mutation, policy editing, package, deploy, release, or authority-expansion
     port.

## Completion gate

All commands must pass exactly and their returns must be appended to
`docs/verification.md`:

```text
uv lock --check
uv sync --dev
uv run python -c "import rci"
uv run pytest -q -m "not optional"
uv sync --all-extras --dev
uv run ruff format --check .
uv run ruff check .
uv run mypy src/rci tests
uv run pytest -q
uv run pytest -q tests/acceptance
uv run rci --help
uv build
```

Blocking evidence additionally shows inert arbitrary payloads; illegal transition
rejection; effect-free replay; CAS tamper and crash recovery; SQLite optimistic
races; request/attempt cardinality; duplicate/late rejection; null/empty/false
distinctions; fail-closed malformed decode/reification; environment
realizability; support and ancestry cycle rejection; guard deactivation;
prediction-before-return; reconstruction/history/knowledge separation; both
predetermined reference conclusions; CLI/SDK parity; and a golden backlog shadow
trace with no unauthorized workspace effects.

## Explicit exclusions

Do not implement passing stubs or claim conformance for full retrieval,
consolidation/reconsolidation, learned probes/automata, executable
`RetentionPackage`/`RecoveryLicense`/`ReacquisitionScaffold`, reacquisition
frontier measurement, compression or the linear theorem, native method
containers, PSR/system identification, the opaque controlled-memory benchmark,
CHC/PDR, controller synthesis, multi-backend evidence, UI/server/deployment, or
release automation. These belong to G2–G7 and remain visible in the requirements
matrix without extending this Goal.

Missing credentials, unavailable optional services, unavailable Docker/GPU, and
deferred research phases do not block G1. Their live conclusions remain
unsupported or unverified.
