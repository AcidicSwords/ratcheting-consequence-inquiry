# ADR-0018: Succession-arrangement compositional inquiry kernel

- Status: accepted; G3K-S promoted, G3K-E stopped indeterminate
- Date: 2026-08-23
- Requirements: RCI-080--RCI-086
- Supersedes: ADR-0016's deferral condition, not its no-collapse rules

## Context

ADR-0016 required two distinct owned verified failure bindings before selecting a
compositional question kernel. G3K-S now reproduces both against the protected incumbent:

1. an admitted generated question carrying answer-conditioned successor rules is rejected
   by the G3Q compiler;
2. a partial return spanning two consequential answer classes becomes one unclassified
   residual and cannot retain both cells as live continuations.

These are different failures: one is static continuation expressivity; the other is
runtime partial-answer representation. They satisfy ADR-0016 without converting a
generated completion into truth or an answer into warrant.

## Decision

Normalize v0.6 around three coupled planes: linear binding-derived succession of typed
effect/return pairs; perpendicular typed arrangement composition; and candidate
recognition of arrangements from owned trace fragments. Questions are typed effects.
Open relations are a conservative static lowering for relational questions, not the
universal definition of question. Boolean logic is the exhaustive closed binary
arrangement specialization. Answer-conditioned continuation is represented by a finite
guarded graph equivalent to `Vis(e, kappa)`; no free-monad dependency is adopted.

Piecewise recognition remains candidate construction. Persistence is a protected
commutation/transport claim across succession. Neither grants actuality, check, warrant,
admission, execution, review, or promotion.

G3K-S changes semantic authority and records the incumbent failures only. G3K-E is a
separate future Goal for executable records, events, folded-state v7, compatibility
projections, and the focused grammar acceptance gate.

## Preserved ADR-0016 constraints

Candidate completions are not true relation members; semantic completion is not an
external return; available observations do not replace protected consequences;
question/probe/method/warrant/promotion admission remain separate; learned probe
admission is not grammar extension; and generated syntax remains inert. Unrestricted
quantification, arbitrary callables, dynamic imports, code payloads, model adapters,
free-monad packages, BDD dependencies, and self-authority remain excluded.
