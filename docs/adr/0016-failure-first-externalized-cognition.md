# ADR-0016: Failure-first externalized cognition

- Status: accepted for active G3FO implementation
- Date: 2026-08-22
- Requirements: RCI-073, RCI-077, and RCI-078

## Context

RCI preserves operational returns, predictions, mismatches, project-development
evidence, and manually authored capability limitations. It does not yet have a pure
deterministic bridge that says which protected task consequence failed, distinguishes
that semantic failure from malformed or unavailable execution, and prepares the next
bounded discriminator after context loss.

Two proposed calculi describe useful general machinery for relations, open ports,
question frames, and operator composition. They do not establish that a general algebra
is the present bottleneck. Implementing that algebra first would risk evaluating it only
with self-authored fixtures.

## Decision

G3FO implements one binding-specific, provider-neutral evaluation boundary before any
generic operator calculus:

1. A content-derived pre-return protocol pins the exact Goal, obligation, competence,
   binding, scope, horizon, actor, route, context, evidence access, budget, expected
   consequence, comparison, decoder, checker, and protected consequence identities.
2. The existing effect, attempt, return, decode, acceptance, prediction, and mismatch
   records remain authority. A pure projector derives pass, protected mismatch, decode
   indeterminacy, operational Unknown, or protocol invalidity.
3. Only a protected mismatch may create an inert capability-limitation candidate.
   Diagnostic causes remain a predeclared frontier until independent evidence narrows
   them.
4. A derived cognitive handoff preserves exact evidence, live localization cells, the
   next discriminator, failed-route exclusions, stopping, and reopening conditions.
5. G3FO adds no event kind, folded-state field, snapshot migration, dependency, model
   adapter, execution port, source writer, Git authority, warrant, review substitution,
   or promotion authority.

## Candidate-source reconciliation

The exact operator-first and canonical-regenerative documents are archived under
`docs/spec/sources/`. They are proposals and derivations, not live instructions. In
particular:

- a completion candidate is not thereby a true member of a relation;
- semantic completion is not an independently captured external return;
- question, probe, method, warrant, and promotion admission remain separate;
- one schema-level discharge label cannot collapse route and stage authority;
- learned probe-instance admission is not generic question-signature extension;
- generic operator composition, free constructions, refinement lattices, and composite
  promotion remain deferred.

G3FO adopts only fixed antecedent localization cells, partial/indeterminate outcomes,
discharge-route pins, and answer-conditioned next discrimination where the observed
failure boundary requires them.

## Consequences

Actual episodes can select a later question-frame, method, representation, adapter,
context, implementation, or authority Goal without allowing a model to diagnose or
promote itself. A generic relation/operator kernel remains a candidate and requires at
least two distinct measured failure bindings before repository-wide generalization.
